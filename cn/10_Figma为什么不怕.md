# 第10章　Figma 为什么不怕：从本地私服到云端内核

> **「figma 若是 Wasm，不是也被看光了？」**
> 是的。`figma.wasm` 的二进位文件会被完整下载到每一位用户的浏览器中，理论上完全「被看光了」。
> **那为什么至今全球没有任何一家公司或黑客团队，能成功山寨出一套一模一样的 Figma？**
> 因为 Figma 在架构设计中，把「低级机器码混淆」与「后端即时协作网络栈」结合到了极致，构建了一条**物理级的商业护城河**。

## 情境 1　第一道防线：数百万行 C++ 的「二进位天书」

**背景**：Figma 的内核二进位文件压缩后体积达数十 MB，里面包含了数百万行极致优化的 C++ 原代码。

**结构完全平坦化**：Figma 在编译时打开了最高等级的 **Link-Time Optimization (LTO)**，所有的 C++ 类别、继承关系、变量名称、函数名称全部被抹去（strip），并被编译成几百万条平坦的 `i32.add`、`local.get` 虚拟机低级指令。

**逆向工程的修罗场**：黑客如果用逆向工具（如 Ghidra）去啃 `figma.wasm`，他们看到的将是一个巨大的、毫无语义的低级状态机。想要从这几百万条指令中逆向出 Figma 独家的「**矢量网格（Vector Networks）**」算法逻辑，其工作量和成本，**远远大于自己从零写一套全新的软件**。

**这里值得补一段技术细节，因为它解释了「规模」本身如何成为防御**：

| 逆向的难度来源 | 为什么规模让它指数级变难 |
|---|---|
| **LTO 打散了函数边界** | 跨编译单元的内联让「一个函数 = 一个逻辑单元」的假设失效。你看到的一个 Wasm 函数，可能是原本五个 C++ 函数融合后的产物 |
| **模板实例化爆炸** | C++ 模板为每种类型生成一份特化代码。逆向者看到的是二十个长得几乎一样、却各有微妙差异的函数，而原代码里只有一个模板 |
| **没有类型、没有结构** | 一个 `struct Node { id, parent, children, transform, style }` 在 Wasm 里只剩下 `i32.load offset=24`。你必须从所有访问位置反推出这个结构的字段布局 |
| **控制流被结构化重写** | 编译器为了符合 Wasm 的结构化控制流（第 2 章），会引入状态变量与 `br_table`，让原本清晰的循环与跳转变形 |
| **规模本身** | 逆向 1,000 行是周末项目；逆向 100 万行是一支团队数年的工程，而且**你还必须同时理解一整个领域**（贝兹曲线布尔运算、字体排版、增量渲染） |

**这条防线的本质不是「不可能」，是「不划算」**——与其花三年逆向出一套你不完全理解、也无法维护的代码，不如花同样的时间自己写一套。**而这正是防御成功的定义。**

## 情境 2　第二道防线：内核商业壁垒在后端

**背景**：这才是 Figma 最致命的护城河——**Figma 不是一个单机绘图软件，而是一个多人即时协作系统。**

**前端 Wasm 的职责**：只负责密集运算。你鼠标拖动一个方块，Wasm 负责用极致速度计算几何矩阵、处理字体排版，并通过 WebGL 渲染出流畅的 60 FPS 画面。

**后端服务器的职责**：当多人同时在同一个画布上修改同一个图层时，数据绝对不能冲突。Figma 后端拥有一整套基于 **CRDT（Conflict-free Replicated Data Type，冲突解决拷贝数据类型）** 的分布式网络引擎。

**CRDT 为什么是一道真正的护城河**（这比「后端有个服务器」深刻得多）：

```
问题：A 和 B 同时把同一个图层往不同方向拖，且网络有延迟。
      最后两边的画面必须一致，而且不能有任何一方的操作「消失」。

天真解法：最后写入者获胜（last-write-wins）
        → 有人的操作会凭空消失，用户会抓狂

Figma 的解法：为文档模型设计一套「操作可交换」的数据结构
        → 不管操作以什么顺序抵达，收敛到同一个状态
        → 图层树的父子关系、属性、排序，每一种都要各自设计合并语意
        → 而且要处理：脱机编辑、历史回溯、权限交错、大文档的增量同步
```

**这套东西的难度不在算法论文里，在无数个边界情境里**：两个人同时把 A 拖进 B、同时把 B 拖进 A，会不会产生环？一个人脱机改了三小时，回来时如何合并？版本历史如何在 CRDT 上表达？**这些是花费数年、数十位工程师的产品经验才能磨出来的东西，而且它全部在服务器上，一行都没有下载到你的浏览器里。**

**防御边界**：黑客即使偷走了前端的 `figma.wasm`，他们拿到的也只是一个「**没有灵魂的空壳渲染器**」。没有后端强大、保密的分布式协作主机支持，这套 Wasm 根本无法运作。

## 情境 3　第三、四道防线：没有明文数据，以及法律

**第三道：Wasm 代码内「不包含任何明文数据」**

前面提过，Wasm 内最容易漏底的是明文本串（第 9 章的禁区一）。Figma 在这点上做了极其严格的资安隔离：

- Figma 的 Wasm 内**没有写死任何 API Key、密码或硬编码字符串**。
- 所有的用户数据、图层结构、甚至是 UI 的文本标签，全部都是在**运行期**，通过加密的 WebSocket 信道从 Figma 服务器动态串流灌入 Wasm 线性内存的。
- **黑客只抓 `.wasm` 文件，里面连一个英文本母的用户数据都找不到。**

**这个设计还有一个副作用值得注意**：因为 UI 文本也是动态灌入的，`.wasm` 里连「这个按钮叫什么」都没有——**逆向者连最基本的语义锚点（通常逆向工程最依赖的就是字符串常数）都拿不到。** 在逆向工程实务上，字符串是最重要的路标；抽掉它，难度不只加倍。

**第四道：商业与法律的物理防御线**

- **黑箱资产认证**：如果某家公司真的出了山寨版，Figma 的法务与安全团队只要去分析对方的网络封包，或使用**二进位特征匹配（binary signature matching）**，就能判定对方是否盗用了 Figma 编译出来的特定 Wasm 代码片段。
- **代价高昂的诉讼**：一经查获盗用二进位代码，将面临知识产权诉讼与相关法律责任，**没有任何一家正经的科技企业敢冒这个风险。**

> ⚠️ 真伪提醒
> 本章关于 Figma 的架构描述，**部分基于 Figma 公开的工程博客（Wasm 迁移、多人协作、渲染管线等主题确有官方文章），部分属于依技术逻辑的合理推论**（例如「所有 UI 文本都动态串流」「后端会做二进位特征匹配」这类具体实作细节，Figma 未公开证实）。**请把它读成一个架构模式的范例，而不是 Figma 内部设计的权威描述。** 另外，「矢量网格（Vector Networks）」确为 Figma 公开宣传的内核技术特色，但其具体算法未公开。

> 💡 君之一席话
> 与君一席话：**当你把一样东西大方地送出去时，你就必须确保它离开你之后是「不完整」的。** Figma 每天把最内核的编译引擎送到全球数亿台电脑里，却依然高枕无忧，靠的不是把东西藏好，而是**把它拆成两半，只送出那一半用不了的**。这是一种在自然界随处可见的策略：种子可以随风飘散，因为它需要土壤才能发芽；蜂巢的每一片蜂蜡都是公开的，价值在蜂群的组织里。这条原理对任何要开源、要开放 API、要分发客户端的人都成立：**你不需要藏住全部，你只需要确保被拿走的那部分，在没有你的另一半时是死的。** 而设计「哪一半是活的」，就是架构师最重要的工作。

## 情境 4　那个最尖锐的追问：如果我不反编译，只是把它在本地跑起来呢？

**背景**：这是整趟调查里最好的一个问题，因为它切中了软件工程最经典的「本地破解与脱机授权」漏洞。

> **「如果它是可以被下载的，那不用完整反编译，只要下载后让它可以在本地跑，Figma 不就无法完整以原本的商业模式进行？」**

**如果只看前端代码，这个推论是对的**：黑客确实不需要完整反编译，只要在本地写一个简单的 Node.js 服务器把 Wasm 跑起来（俗称 local splicing），软件看似就能动了。

**然而 Figma 不怕，是因为它在设计之初，就把「网络拓扑架构」与「内核商业模式」死死绑在云端。** 即使黑客把 `figma.wasm` 下载并在本机（`localhost`）强行运行，以下四道物理级防御会让破解版变得毫无商业价值：

### 防御一：文件根本不保存在本机

**传统单机软件（Photoshop、AutoCAD）之所以能被完美破解并脱机使用，是因为它们的文件（`.psd`、`.dwg`）就存在用户自己的硬盘里。**

**Figma 的设计完全相反**：Figma 的画布和项目文件，在你的电脑硬盘里**完全不存在**。你看到的画面，是后端数据库将图层转化为巨型二进位节点流（node stream），动态传输到 Wasm 的线性内存中渲染出来的。

**物理断层**：当黑客在本地 `localhost` 运行 `figma.wasm` 时，这块虚拟机内存是**绝对空无一物**的。本地私服没有 Figma 云端那套庞大的数据库与分布式文件保存集群，它根本**没有任何项目文件可以打开或读取**。

**这句话值得停下来想三秒**：一个没有文件的绘图软件，是一张永远打不开任何东西的白纸。**破解者得到的不是一个免费的 Figma，是一个空白的画布程序。**

### 防御二：内核算力留在云端

Figma 并非把 100% 的软件功能都编译进 Wasm，而是做了严格的**算力拆分**：

| 本地 Wasm 负责 | 云端后端负责 |
|---|---|
| UI 交互与即时渲染（鼠标拖曳、贝兹曲线控制、WebGL 绘图） | 团队权限验证 |
| 几何矩阵运算、字体排版 | 字体库动态加载 |
| | 多文件版本控制与历史回溯 |
| | **CRDT 多人即时同步引擎** |
| | 资产库、组件库、设计系统的分发 |

**破解版的代价**：黑客在本地跑这个 Wasm，拿到的是一个「**无法邀请团队协作、无法保存文件、无法自动更新、没有版本纪录、且无法加载自订字体**」的残废单机绘图板。对于 Figma 最内核的付费客户（企业设计团队、产品经理、前端工程师）来说，这种破解版**完全无法投入真正的工业生产**。

### 防御三：买的不是软件，是「协作效率」

Figma 的商业模式是 **B2B SaaS**，它的收费对象不是独立的个人设计师，而是「整个科技公司的产品研发团队」。

- **企业的痛点**：企业之所以愿意每个月为每个员工支付订阅费，买的不是「画方块和圆形的功能」，而是买「设计师画完、产品经理能立刻在线评论、前端工程师能一键拷贝 CSS」的**协作效率与信任边界**。
- **私服的致命伤**：没有任何一家正经的科技公司会为了省下订阅费，去让员工下载黑客做的「本地破解版 Figma」。这不仅完全丧失了多人即时协作的灵魂，更会让企业面临严重的资安漏洞、知识产权诉讼与数据外泄风险。

### 防御四：后端对客户端的动态校验

现代云端应用的后端通常会布建这道防线：

- **动态握手（handshake tokens）**：当前端 Wasm 启动并与后端创建 WebSocket 连接时，后端会对客户端做动态的指纹与完整性校验。
- **秒级封杀**：如果黑客尝试修改前端代码以绕过登录，或在非授权的网域（如 `localhost`）下发起连接，后端安全闸道会识别出这是一个「伪造的客户端」，并立刻拒绝向其串流任何画布数据，让本地 Wasm 卡死在加载画面。

> ⚠️ 真伪提醒
> 防御四描述的是业界常见的做法（Origin 检查、token 绑定、客户端完整性证明），但**「对 Wasm 的内存哈希值做动态指纹校验」这种具体手法，在技术上是脆弱的**——客户端的任何自我校验都可以被本地修改绕过（这是「客户端不可信」这条资安铁律的直接推论）。真正有效的是**服务器端的授权判断**（这个 token 属于哪个帐号、有没有付费、有没有这份文件的权限），而不是客户端的自证清白。**把防御重心放在客户端完整性校验，是一种常见但根本站不住的设计。**

> 🔍 进阶点评──从「防拷贝」到「防无用」，软件防护史上最大的一次范式转移
> 这一整章其实是在讲一场已经完成、但很多人还没意识到的范式转移。**单机时代的防护目标是「不让你拷贝」**——序号、狗（dongle）、加壳、在线激活、DRM。这场仗防守方输了三十年，因为它在数学上必输：**你把一个完整的、可独立运作的东西交到对方手上，同时要求他不能用它。** 这是自相矛盾的要求，破解只是时间问题。**云端时代的防护目标变成「让拷贝品没有用」**——不是不让你拿走客户端，而是确保客户端在离开服务器之后是一个空壳。这场仗防守方会赢，因为它不再要求任何矛盾的事：**东西你随便拿，因为东西本身不是价值；价值在数据、在协作关系、在那条你连不上的线里。** 而这个转移带来一个对所有产品人都重要的推论：**「防拷贝」是一个技术问题，而技术问题总有被破解的一天；「防无用」是一个架构问题，而架构问题一旦设计对了，就不再需要被防守。** 所以当你发现自己在为「怎么保护我的代码」投入大量精力时，那多半是一个信号——**说明你的价值还放在错误的地方。** 正确的动作不是加强保护，是把价值搬家。
>
> 但这里还有一个更深的问题没有回答：**如果 Figma 的护城河已经不是技术了，而是数据、协作与生态，那当开源社群把技术部分完全商品化之后，这条河还能护多久？** 这正是下一章要处理的。

## 本章小结

- Figma 的第一道防线是**规模造成的逆向成本**：LTO 打散函数边界、模板实例化爆炸、结构与类型全失、控制流被重写，再加上一百万行的体量与领域门槛——**逆向的工作量远大于从零重写，而这正是防御成功的定义。**
- 第二道防线是**内核商业壁垒在后端**：CRDT 即时协作引擎的难度不在论文里，在无数边界情境里，而且它一行都没有下载到浏览器。**偷走 `figma.wasm` 只是拿到一个没有灵魂的空壳渲染器。**
- 第三道是**二进位里没有任何明文数据**（连 UI 文本都是运行期串流灌入）——这同时抽掉了逆向工程最依赖的语义路标。第四道是**法律与二进位特征匹配**。
- 最尖锐的追问「不反编译，直接在本地跑」被四件事挡死：**文件根本不在本机**（空白画布）、**内核算力在云端**（残废单机版）、**企业买的是协作而非功能**、**后端对客户端的授权判断**（但要注意：客户端自我校验在技术上站不住，见情境 4 ⚠️）。
- 这是一场**已经完成的范式转移**：从「防拷贝」（技术问题，防守方必输）到「防无用」（架构问题，设计对了就不必再防）。
- **推论**：如果你发现自己在为「保护代码」投入大量精力，那是价值放错位置的信号。**正确的动作不是加强保护，是把价值搬家。**

但这道护城河创建在一个假设上——**技术壁垒足够高，别人短期内做不出来。** 如果那个假设不再成立呢？翻到第 11 章。
