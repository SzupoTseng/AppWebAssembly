## 序　那台跑在别人电脑上的机器

二〇二六年夏天的某个下午三点四十分，一个很普通的问题被打进搜索框：

> **「请细说 WebAssembly 的发展史、优缺点、竞品、著名的应用或是开源项目。」**

那是一个所有工程师都问过的入门问题。可是接下来的一个多小时里，这条对话没有停在入门处。它从「Wasm 是什么」滑到「Wasm 的限制是什么」，再滑到一个看似无关的岔路——「GitHub Pages 的网页是静止的吗？可以跑 server？」——然后就再也回不去了。

因为那个岔路的尽头，藏着一个令人不安的事实：**一个一毛钱都不用付的静态网页空间，配上一颗 Wasm 引擎，就能跑起 FFmpeg、跑起 Linux、跑起 SQL 数据库、跑起大型语言模型。** 服务器不是变便宜了，是被整个拿掉了。运算没有消失，它只是被推到了每一个打开网页的人的 CPU 上。

于是那条对话问出了下一个问题：那别人都在上面跑什么？答案滚了一百二十条。

然后在滚到第一百二十条之后，对话突然转向，问了一个和技术无关、却让整件事重新排列的问题：

> **「在 GitHub Pages 跑程序，不是被看光了？」**

是的，完全被看光了。你的 `.wasm` 文件会被完整下载到每一台陌生的电脑上。

> **「Figma 若是 Wasm，不是也被看光了？」**

也是的。`figma.wasm` 每天被下载到全球数亿台电脑里。

> **「那不用完整反编译，只要下载后让它在本地跑，Figma 不就无法以原本的商业模式进行？」**

这就是这本书真正的起点。**因为答案是「不会」，而理解为什么「不会」，比理解 Wasm 本身更重要。**

### 三种东西，混在同一锅里

这趟调查的原始材料，是一份混杂的技术对话纪录。里头浮着三种料，把它们捞开分清，是这本书的第一课：

1. **站得住的事实**：Wasm 的二进位格式与类型系统、线性内存的 4GB 寻址上限、COOP/COEP 与 `SharedArrayBuffer` 的因果、OPFS 的 `createSyncAccessHandle`、WASI 的能力式安全模型、Figma 与 Photoshop Web 确实靠 Wasm 把 C++ 搬上浏览器。这些都可以查证、可以复现。
2. **查不到底的说法**：对话中出现的一百二十个「经典案例」里，有相当一部分是**真实存在且知名的开源项目**（FFmpeg.wasm、v86、Pyodide、DuckDB-Wasm、SQLite-Wasm、esbuild、Stockfish、OpenCV.js……），但也有相当一部分是**依技术逻辑构造出来的示意案例**（`Web-Biconical`、`Espace3D-Wasm`、`Cubism-OLAP-Wasm`、`Hologram3D-Wasm`……）——它们描述的技术路径成立，但**项目本身未经查证、极可能不以该名称存在**。书中一律标「⚠️ 真伪提醒」。所有「快 N 倍」「达原生 X%」的数字同理：**信其量级，疑其小数点。**
3. **会误导人的直觉**：「二进位很难逆向，所以安全」「被看光就没有商业模式」「Token 便宜了，所有软件都能自己造」。这三句话都有一半是对的，而正是那另一半，决定了你的架构会不会在两年后崩掉。

> ⚠️ 全书的真伪纪律
> 本书横跨可查证的规范事实与未经查证的社群说法。凡属后者一律标「⚠️ 真伪提醒」。**规范层面的叙述（二进位格式、规范状态、浏览器 API 行为）请以 WebAssembly 官方规范、MDN 与各引擎的实作文档为准**——本书以 **WebAssembly 3.0**（2025 年 9 月完成）为基准写成，而这是一个仍在移动的领域。**任何把 GC／memory64／尾调用／例外处理称为「提案」的数据，都写于 3.0 之前。**

### 三个乐章：懂它、用它、守它

- **第一乐章　懂它（第 1–4 章）**：Wasm 不是「更快的 JavaScript」，它是一台**规格被写死的抽象机器**——堆栈式虚拟机、结构化控制流、单一连续的线性内存、编译期就能证明安全的类型系统。它快，不是因为它聪明，是因为它**什么都不让你动**。而 2015 年为了让四家浏览器坐上谈判桌所砍掉的每一样能力，用了整整十年逐条加回来——**到 2025 年 9 月的 WebAssembly 3.0，那笔债基本还清了。** **目标：知道这台机器的每一条物理定律，因为后面所有的限制都是这些定律的直接推论。**
- **第二乐章　用它（第 5–8 章）**：一台机器最有趣的地方，是它能跑在**不该跑得动它的地方**。GitHub Pages 不给你设 HTTP Header、不给你开连接端口、不给你一行后端代码——而社群硬是在上面跑起了影音转码、x86 仿真器、OLAP 数据库与 LLM 推理。**目标：让机器真的动起来，并且知道它会在哪一格撞墙。**
- **第三乐章　守它（第 9–12 章）**：当你的机器被完整下载到每一台陌生的电脑上，你还剩下什么？答案不在混淆器里，在架构图上。**目标：画出那条「哪些算力送出去、哪些关系链锁起来」的边界线——这条线在 LLM 把写程序的边际成本压到接近零之后，是唯一还站得住的东西。**

而如果你想先看一个**同时完成了这三件事的真实例子**——一台把编译器、虚拟机、telnet 协定全部搬进浏览器分页的 MUD 服务器，它的全部原代码三十年来一直可以被完整下载，而它的价值一分都没有因此消失——**直接翻到附录 L。** 那是全书内核命题最干净的一具活体标本。

懂它、用它、守它——这三个动词彼此咬合。第一乐章那条 4GB 的线性内存上限，直接决定了第二乐章的 FFmpeg.wasm 为什么吃不下 4K 大档；而第二乐章「把算力免费推给客户端」的甜头，正是第三乐章那道护城河**必须**建在别的地方的原因。

> 💡 **全书的内核命题**
> **能被下载的，迟早会被拷贝；不能被搬走的，才是护城河。**
> Wasm 把运算变成了可以无限拷贝、零成本分发的东西——这既是它最大的礼物，也是它对商业模式最彻底的破坏。真正的架构功力，不在于把代码藏得多好，而在于**清楚知道哪些东西本来就藏不住，然后把价值放到别的地方去。**

### 关于书名

**汇编语言死过一次。**

它曾经是唯一贴着机器的语言，然后被高级语言一层层抽象掉，变成一门只有少数人还在写、且绑死在某一颗 CPU 上的手艺。**它死于不可携——一段 x86 汇编搬到 ARM 上就是一堆废字节。**

而它回来了，只是换了一具身体：**这一次，它的机器不存在。**

WebAssembly 是一台规格上定义出来、物理上并不存在的抽象堆栈机器的汇编语言。**正因为那台机器不存在，它才到处都在**——它此刻正在你打开的分页里、在几十亿台你永远不会见到的电脑里，安静地运转，而它们的主人多半不知道。

**一具没有形体、看不见、却无所不在的东西，中文有一个现成的词。**

而这本书真正想讲的，是这只幽灵飘进别人家里之后的事——**你送出去的那份东西，还算不算你的？**

每章末留一句「💡 君之一席话」当作当晚的笔记；再附一段「🔍 进阶点评」，深掘该案背后的工程现实与那条看不见的路。
